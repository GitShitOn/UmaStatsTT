# UmaStatsTT

Analysis of *Uma Musume Pretty Derby* **Team Trials** results. It reads the JSON files from
your sessions (`TT-YYYYMMDD_hhmmss_xxx.json`) and shows where your points come from, where
you lose them, and what is worth improving to raise your score.

It also decodes each race's binary replay (`race_scenario`). From the replay it gets every
uma's score events, activated skills, HP, start delay, rushed periods and final spurt.

You can use it in two ways: as a **web app** in the browser, or as a **Python script** from
the terminal. The calculations are the same.

**Online:** https://gitshiton.github.io/UmaStatsTT/

## Web app

The `web/` folder holds a static web app: no server, nothing to install. Drop your
`TT-*.json` files on the page and the analysis runs in your browser. The files are not sent
anywhere, and the page remembers them on your device until you press "Clear".

- **From disk:** double-click `web/index.html`.
- **Single file to share or use offline:** `python3 web/build.py` creates
  `dist/UmaStatsTT.html`, with styles, code and skill names inside.
- **Online with GitHub Pages:** the `.github/workflows/pages.yml` workflow publishes `web/`
  on every push to the default branch that changes the web app. One-time setup:
  Settings → Pages → Build and deployment → Source: **GitHub Actions**. Then start
  "Deploy web app to GitHub Pages" from the Actions tab with *Run workflow* (or push).
  The address is `https://<user>.github.io/UmaStatsTT/`. Any other static hosting works
  too: just upload the contents of `web/`.

The page contains:
- a summary with the key numbers and the 5 actions worth the most;
- a chart of the score by session;
- where the points come from;
- results by distance;
- each uma's points split by source, with diagnostics and a card (races and skills);
- your stats compared with your opponents';
- skills that never fired;
- race-by-race details;
- priorities;
- a legend;
- CSV export to the clipboard.

| File | Role |
|---|---|
| `web/engine.js` | Analysis: reading the files, decoding the replay, statistics, recommendations. Also runs in Node |
| `web/app.js` | Interface: loading files, charts, tables |
| `web/index.html`, `web/style.css` | Page and styles (light and dark theme) |
| `web/skill_names.js` | Skill names, generated by `tt_stats.py --update-names` |
| `web/demo.js` | Sample data shown when the page opens (empty in the repository) |

## Script requirements

Python 3.8 or newer, no external libraries.

## Script usage

```bash
# put the TT-*.json files in ./data (or pass files/folders as arguments)
python3 tt_stats.py
python3 tt_stats.py data/
python3 tt_stats.py TT-20260909_180032_837.json TT-20260909_180753_776.json

# options
python3 tt_stats.py data/ --details              # race-by-race breakdown
python3 tt_stats.py data/ --skills               # full skill table for every uma
python3 tt_stats.py data/ --md report.md         # also save as Markdown
python3 tt_stats.py data/ --csv export/          # export the data as CSV for Excel/Sheets
python3 tt_stats.py --update-names               # download the names of newly released skills
```

## Skill names

Global skill names and rarity (white, gold, unique) are in `skill_names.json`, next to the
script, one skill per line: `"200432": ["Focus", 1]`. The data comes from the
[alpha123/uma-tools](https://github.com/alpha123/uma-tools) project
(`umalator-global/skillnames.json` and `skill_data.json`), extracted from the Global client text.

- When new skills come out, `python3 tt_stats.py --update-names` downloads the file again
  and also refreshes `web/skill_names.js` for the web app. In the web app you can also drop
  a JSON file of names together with your session files.
  Skills without a name are shown by their ID, and the report says so.
- `--skill-names FILE.json` adds or replaces names, for example to translate them. It accepts
  `{"200012": "Name"}`, `{"200012": ["Name", 1]}` or `[{"id": 200012, "name_en": "Name"}]`.

## What the report contains

| Section | What it is for |
|---|---|
| Summary | The 5 actions worth the most, in estimated final points per session, plus aptitudes below A |
| Sessions | Score, wins and losses, opponent rating and multipliers for each session |
| How the score is built | Percentage bonuses seen and how much 1 base point is worth |
| Where the points come from | Weight of each category (finishing position, skills, start, ...) in the total |
| By distance | Points, wins, average place and team bonus for Sprint, Mile, Medium, Long and Dirt |
| Performance by uma | Finishes, base and final points per race, split by source |
| Diagnostics by uma | Skills per race, unique activations, perfect starts, "leads own strategy", rushed, out of HP, late spurt, HP left, time blocked |
| Stats and aptitudes | Stats, aptitudes, theoretical skill-activation and rushed chances (from WIT), mood |
| Us vs opponents | Average stats compared by distance, and who won the races you lost |
| Random factors | Effect of mood and frequency of perfect starts |
| Skills | Activations and points per skill, skills that never fired |
| What to improve | Full list of priorities, with an estimated gain |

## How the score works (derived from the data)

Every event is worth **base points**. Each item is then multiplied by `1 + bonuses`, and the
team bonus is added at the end. The script checks that the sum matches `team_total_score`.

| Event | Base points |
|---|---|
| Finishing position | 1st 10,000, 2nd 8,000, 3rd 7,000, 4th 6,000, 5th 5,000, 6th-7th 4,000, 8th 3,000, 10th-12th 2,000 |
| Winning margin (1st place only) | bigger margin = more points (1,000-2,200 seen) |
| White skill / inherited unique | 500 per activation (passive skills count too) |
| Gold skill | 1,200 per activation |
| Unique skill | 2,300-2,500 (grows with level) |
| Perfect start | 1,000 when the start delay is under 0.02 s |
| Leads own strategy at 1/6 of the race | 1,000 if you are ahead of every uma with your same strategy |
| Leads own strategy at 2/3 of the race | 1,000, same rule at the start of the final phase |
| Time bonus | +100 per 0.1 s under a course reference time |
| Rushed | -500 when it starts, -100 for every second |
| Upset (inferred) | 3,000-4,000 for a 1st/2nd place as an outsider |
| Team | +4,000 if all 3 finish in the top 5, +5,000 if all 3 finish in the top 3 |

| Percentage bonus | Value seen |
|---|---|
| Opponent | about +155%, grows with the opposing team's rating |
| Support cards | `support_card_bonus` / 100 (e.g. 1018 = +10.18%) |
| First uma of the distance (slot 1) | +10% |
| Win streak | +2% on the 2nd win in a row, +3% on the 3rd, ... |

In practice 1 base point is worth about 2.65 final points. What moves your score is base points.

## If you change your team between sessions

Every trained uma is recognized by its `trained_chara_id`, so the stats of different umas
never get mixed, even when they are the same character.

- The **current team** is the one in the latest session: the order comes from the date in
  the `TT-YYYYMMDD_hhmmss` file name. The advice covers only the current team.
- Umas that left stay in the statistics, marked **(former)**, and generate no advice.
- If you retrain the same character, the versions become `v1`, `v2`, ... in order of
  appearance.
- A section lists the changes between sessions: umas in, out, and moved to another distance
  or slot.
- The report flags umas with fewer than 3 races, and does not judge the unique skill after
  a single race.

## Limits

- The files contain your team's scores, not your opponents'.
- Rules marked "inferred" are based on few cases.
- The Wit-based chances use well-known community formulas and are indicative:
  skill `max(100 - 9000/WIT, 20)%`, rushed `(6.5 / log10(WIT/10 + 1))^2 %`.
- The estimated gains are meant to rank priorities, not to predict exact results.
